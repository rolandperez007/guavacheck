# Guava Inc. Code of Conduct

Version: 1.0

Status: Active

Owner: Guava Inc.

Classification: Repository Standard

---

# Purpose

This Code of Conduct establishes the standards expected of every individual who contributes to guavacheck.

Whether contributing code, documentation, designs, ideas, testing, research or feedback, every participant shares responsibility for protecting the quality, integrity and reputation of the platform.

This document exists to ensure that collaboration remains respectful, professional and productive.

---

We believe exceptional software is built by exceptional people working together.

Technical excellence alone is not enough.

Professionalism.

Integrity.

Respect.

Humility.

Curiosity.

Accountability.

These qualities are equally important.

# Expected Behaviour

Contributors are expected to:

Treat others professionally.

Communicate respectfully.

Accept constructive feedback.

Provide constructive feedback.

Support collaborative problem solving.

Document their work clearly.

Respect differing viewpoints.

Ask questions when uncertain.

Protect confidential information.

Take responsibility for mistakes.

Celebrate the success of others.

Seek long-term solutions instead of short-term shortcuts.

---

# Engineering Standards

Every contribution should strive for:

Clarity.

Security.

Maintainability.

Reliability.

Scalability.

Performance.

Consistency.

Documentation.

Testing.

Every pull request represents the reputation of Guava Inc.

---

# Communication

Healthy discussion is encouraged.

Disagreement is normal.

Disrespect is not.

When discussing technical decisions:

Focus on evidence.

Explain reasoning.

Remain objective.

Avoid personal criticism.

Assume positive intent.

The best idea should win.

Not the loudest voice.

---

# Diversity of Thought

Innovation depends upon different experiences.

Different perspectives strengthen products.

Constructive disagreement improves engineering.

Every contributor should feel comfortable presenting ideas respectfully.

---

# Professional Integrity

Contributors should never knowingly:

Introduce malicious code.

Hide security vulnerabilities.

Falsify testing.

Misrepresent results.

Steal intellectual property.

Plagiarize code.

Bypass review processes.

Compromise user trust.

Integrity is non-negotiable.

---

# Security Responsibility

Security belongs to everyone.

Contributors should:

Protect credentials.

Protect user data.

Report vulnerabilities responsibly.

Avoid exposing confidential information.

Follow secure coding practices.

Review security implications before submitting code.

---

# Documentation

Documentation is part of the product.

Every significant architectural decision should be documented.

Every new engine should be documented.

Every public API should be documented.

Good documentation reduces future mistakes.

Accuracy.

Security.

AI is a tool.

Responsibility remains human.
