\# Guava Iconography



> The official icon system for the Guava platform.



\---



\# Overview



Icons provide visual recognition without replacing text.



Every icon should improve comprehension while maintaining the calm and professional appearance of the platform.



Icons are supporting elements.



They should never become the dominant visual feature.



\---



\# Design Philosophy



Icons should be:



Simple



Recognisable



Consistent



Scalable



Professional



Timeless



Avoid decorative illustrations.



Every icon must communicate a clear action or concept.



\---



\# Icon Library



The preferred icon library is:



\*\*Lucide Icons\*\*



Reasons:



\- Consistent stroke design

\- Excellent readability

\- Open source

\- React friendly

\- Tree-shakeable

\- Large ecosystem



Custom icons should only be introduced when no suitable icon exists.



\---



\# Icon Style



Outlined icons are the default.



Filled icons should only indicate:



\- Active navigation

\- Selected state

\- Important status

\- Notifications



Maintain one visual style throughout the application.



\---



\# Stroke Width



Default:



2 px



Do not mix stroke weights.



\---



\# Corner Style



Rounded joins.



Rounded line caps.



Maintain a soft and modern appearance.



\---

16 px

\---



\# Navigation Icons



Sidebar icons:



20 px



Top navigation:



20 px



Dashboard quick actions:



24 px



Feature highlights:



32 px



Maintain consistent sizing within each context.



\---



\# Dashboard Icons



Dashboard cards should use restrained iconography.



Icons support the content.



They do not replace headings.

\---



\# Notifications



Notification icons should always match semantic colors.



Success



Green



Warning



Amber



Error



Red



Information



Blue



\---



\# Hover Behaviour



Icons may slightly change opacity or color on hover.



Avoid exaggerated scaling or rotation.



\---



\# Disabled Icons



Reduce opacity.



Do not alter icon shapes.



\---



\# Accessibility



Icons must never be the only method of communicating meaning.



Provide:



Labels



Tooltips



Accessible names



Screen reader support



\---



\# Figma Components



Every icon should exist as a reusable component.



Avoid detached icon instances.



\---



\# Engineering



Expose icons through a shared component library.



Example:



Icon



↓



Button



↓



Navigation



↓



Dashboard



↓



Feature



Maintain a single import path.



\---



\# Icon Principles



Icons should be:



Consistent



Minimal



Readable



Purposeful



Accessible



Reusable



\---



\# Iconography Statement



Guava icons support navigation and understanding without distracting from content.



They reinforce familiarity, improve recognition, and contribute to a calm, professional interface.
