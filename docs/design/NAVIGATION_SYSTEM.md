\# Guava Navigation System



> The navigation architecture for the Guava City ecosystem.



\---



\# Overview



Navigation in Guava is not based on disconnected pages.



It is based on moving through a living digital city.



Every major capability belongs to a district.



Users should always feel that they are travelling through one connected ecosystem rather than jumping between unrelated applications.



Austin accompanies the user everywhere.



\---



\# Navigation Philosophy



The dashboard is the city entrance.



Every destination begins there.



Every workflow eventually returns there.



The dashboard is not simply another page.



It is the permanent home of the user.



\---



\# Core Navigation Model



```

Dashboard



↓



District



↓



Workspace



↓



Result



↓



Dashboard

```



Users should never feel lost.



Every workflow forms a complete loop.



\---



\# Dashboard



The dashboard serves as:



\- Home

\- Activity Center

\- Notification Center

\- Austin Entry Point

\- Recent Projects

\- Quick Actions

\- City Overview



Everything begins here.



\---



\# Sidebar Navigation



The left sidebar is the permanent city map.



It remains visible throughout desktop usage.



Sections should remain in a consistent order.



Example:



Dashboard



Marketplace



Property Passport



Construction



Finance



Investor



Knowledge



Projects



Reports



Settings



Austin



The order should rarely change.



Consistency improves orientation.



\---



\# District Navigation



Every district represents a complete area of expertise.



Examples:



Marketplace District



Property Passport District



Construction District



Finance District



Investor District



Knowledge District



Future districts should follow the same architectural principles.



\---



\# District Identity



Every district has:



Dedicated icon



Primary colour accent



Landing page



Austin awareness



Independent navigation



Contextual actions



Shared design language



Districts should feel unique without feeling like different products.



\---



\# Austin Navigation



Austin is available from every location.



Users may:



Ask quick questions



Continue conversations



Open Workspace



Resume previous work



Austin never requires users to leave their current context.



\---



\# Workspace Navigation



When a task becomes more detailed:



Dashboard



↓



District



↓



Austin Workspace



The workspace opens without replacing the dashboard.



The user remains connected to the city.



\---



\# Breadcrumbs



Every major page displays a breadcrumb.



Example:



Dashboard



>



Marketplace



>



Property Details



>



Verification



Users should always understand where they are.



\---



\# Back Navigation



The Back action should return users to the previous logical step.



Never to an unexpected location.



Navigation history should feel predictable.



\---



\# Quick Actions



Frequently used actions should remain accessible.



Examples:



Search



Ask Austin



Upload Document



Verify Property



Estimate Construction



Generate Passport



New Listing



These actions reduce unnecessary navigation.



\---



\# Contextual Navigation



Navigation changes according to the user's current task.



Example:



Inside Property Passport



Austin recommends:



Ownership Verification



Construction Estimate



Market Analysis



Mortgage Options



The interface anticipates the next likely action.



\---



\# Search as Navigation



Search is not merely a lookup tool.



It is a navigation mechanism.



Users may navigate directly by asking:



"Show my projects."



"Open Finance."



"Go to Marketplace."



"Show Lagos properties."



Austin understands these requests and navigates appropriately.



\---



\# Notifications



Notifications should include direct navigation.



Example:



Construction estimate completed.



↓



Open Results



Users should never need to search for completed work.



\---



\# Deep Links



Every important screen should support direct navigation.



Examples:



Property Passport



Project



Listing



Construction Estimate



Mortgage Report



Verification Report



Austin Conversation



Deep links enable collaboration and sharing.



\---



\# Persistent Context



Changing pages should not interrupt active work.



Austin remembers:



Current conversation



Selected property



Filters



Active project



Workspace state



Users continue where they left off.



\---



\# Multi-Window Behaviour



Users may have multiple workspaces open.



Each workspace maintains its own state.



Austin understands which workspace is active.



\---



\# Mobile Navigation



Mobile prioritises simplicity.



Primary navigation becomes a bottom navigation bar.



Austin remains accessible through the dashboard hero and a persistent action button.



Complex work opens in full-screen workspace views.



Navigation depth should remain shallow.



\---



\# Keyboard Navigation



Support:



Tab



Arrow Keys



Escape



Enter



Keyboard shortcuts



Power users should navigate rapidly without relying on the mouse.



\---



\# Navigation Principles



Navigation should always be:



Predictable



Consistent



Minimal



Context-aware



Fast



Discoverable



Professional



Users should never wonder:



"Where do I go next?"



\---



\# Navigation Statement



Guava's navigation is designed around the concept of a connected digital city.



Users move naturally between districts while Austin provides continuous assistance and preserves context.



The result is an experience that feels unified, intuitive, and productive regardless of how large the platform becomes.
