# Austin Memory Model

**Version:** 1.0.0

**Status:** Living Document

---

# Purpose

The Memory Model defines how Austin stores, retrieves and manages contextual information throughout the lifecycle of user interactions.

The objective is to create continuity without unnecessary repetition while respecting privacy and user control.

---

# Memory Philosophy

Austin should remember what is useful.

Austin should forget what is unnecessary.

Austin should never surprise users with inappropriate memory.

---

# Memory Layers

Long-Term Memory

↓

Project Memory

↓

Session Memory

↓

Working Memory

---

# Working Memory

Purpose:

Maintain information required to complete the current task.

Examples:

- Current property
- Current construction project
- Current calculation
- Active conversation

Working memory is discarded when no longer required.

---

# Session Memory

Purpose:

Maintain context throughout an active user session.

Examples:

- Previous questions
- Selected property
- Active filters
- Temporary preferences

---

# Project Memory

Purpose:

Maintain continuity for long-running projects.

Examples:

- Construction plans
- Renovation history
- Property portfolio
- Investment analysis
- Enterprise planning

---

# Long-Term Memory

Purpose:

Store persistent user preferences.

Examples:

- Preferred language
- Preferred currency
- Preferred units
- Saved projects
- Subscription tier

---

# Privacy Principles

Users remain in control of persistent memory.

Memory should be:

- Transparent
- Secure
- Auditable
- Deleteable
- Portable

---

# Future Evolution

Future versions may introduce:

- Collaborative memory
- Organization memory

- Shared enterprise workspaces
